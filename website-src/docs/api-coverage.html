API coverage

MikroTik MCP does not cover every RouterOS command yet, and it does not pretend to. The API coverage checklist compares the tools with the official RouterOS manual, command by command, so you can see what is covered and what is still planned.

Where to find it

The checklist lives in the project repository, and the manual it is measured against is MikroTik's own.

API coverage on GitHub ↗ Official RouterOS manual ↗

What the checklist shows

  • Commands, grouped by area. The RouterOS menus the project covers, such as interfaces, IP, IPv6, queues, users, system, files and routing, each with the commands the manual lists for it (add, print, set, remove and so on). Menus that are deliberately left out are listed too, under out of scope.
  • The tools behind each command. An implemented command names the MCP tools that cover it. For example, print on /interface/vlan maps to list_vlan_interfaces and get_vlan_interface.
  • A status for each command. Every command is in exactly one of these states:
StatusMeaning
implementedA tool exists and maps to the command.
partialA tool exists, but some of the behaviour it advertises is missing.
plannedIn scope, but there is no tool yet.
legacyA tool exists only for the older RouterOS v6 path.
not applicableThe command does not exist on RouterOS 7.

How to read it

  • A checked box means a tool exists and its declared parameters map to the manual. It does not prove the command works on every RouterOS version.
  • The progress figure at the top counts commands, not tools, and only for the menus the project has declared. Menus outside that scope are not part of the total.
  • Legacy RouterOS v6 commands count as not implemented, because MikroTik MCP targets RouterOS 7.
  • The version of the manual the checklist was compared against, and when that manual was built, are recorded at the top.

How it stays accurate

The checklist is generated, never edited by hand. A validator in the repository checks that every tool the server registers is declared in the coverage manifest, and that every declared tool really exists. A separate workflow, started by a maintainer, compares the manifest with a pinned snapshot of the manual and reports drift, such as new menus or arguments, for review.

NOTE
This runs at build and review time only. It does not run inside the MCP server and it never connects to your router.

MikroTik MCP

An open-source MCP server bridging large language models with RouterOS devices — plus routeros-lsp, a language server for RouterOS scripts, and routeros-skills, agent skills that teach AI agents RouterOS. Not affiliated with MikroTik.
