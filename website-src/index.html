01 — What it is

The connective tissue between LLMs and RouterOS.

MikroTik MCP is a Model Context Protocol server. It exposes your RouterOS device's configuration surface as typed tools — your AI client picks the right one, fills in the parameters, and runs it over SSH. You stay in the loop; the model just handles the syntax.

// 01

Natural language → typed tools

Every RouterOS noun has a verb. "Make a VLAN" maps onto mikrotik_create_vlan_interface with strict, validated arguments. No hallucinated CLI.

// 02

Three transports, one server

Run it over stdio for desktop AI clients, expose it as SSE for streaming agents, or wrap it in HTTP for REST consumers via mcpo.

// 03

Safe-mode aware

Wrap risky operations in RouterOS safe-mode sessions. If a change locks you out, the device rolls everything back automatically — no manual recovery.

03 — How it works

From English to /ip vlan add in three hops.

The MCP server advertises typed tools to your AI client. The client picks the right one based on context, fills the parameters, and posts back. The server validates, translates to RouterOS CLI, and runs it over SSH against your device.

01
Client discovers tools. On startup the AI client queries the server for available tool schemas and descriptions.
02
Model selects + fills. Given your prompt, it picks the right tool and constructs validated arguments.
03
Server executes. The tool handler builds the RouterOS command, runs it over SSH, and returns structured output.
04
Model summarizes. The result feeds back to the model, which explains the outcome in plain English.
04 — Install

Up in about a minute.

Pick a transport, paste a config, point it at your router. The Docker route is the shortest — no Python toolchain required.

# Build & run the container
# Clone & build
$ git clone https://github.com/wiresage/mikrotik-mcp.git
$ cd mikrotik-mcp
$ docker build -t mikrotik-mcp .

# Run with stdio (IDE integration)
$ docker run --rm -i \
    -e MIKROTIK_HOST=192.168.88.1 \
    -e MIKROTIK_USERNAME=sshuser \
    -e MIKROTIK_PASSWORD=your_password \
    -e MIKROTIK_PORT=22 \
    mikrotik-mcp
# Manual / Python install
$ git clone https://github.com/wiresage/mikrotik-mcp.git
$ cd mikrotik-mcp

# Create & activate venv
$ python -m venv .venv
$ source .venv/bin/activate

# Install + run
$ pip install -e .
$ mcp-server-mikrotik
# ~/Library/Application Support/Claude/claude_desktop_config.json
{
  "mcpServers": {
    "mikrotik": {
      "command": "uvx",
      "args": [
        "mcp-server-mikrotik",
        "--host",     "<HOST>",
        "--username", "<USERNAME>",
        "--password", "<PASSWORD>",
        "--port",     "22"
      ]
    }
  }
}
# HTTP/SSE transport via Docker
$ docker run --rm -p 8000:8000 \
    -e MIKROTIK_HOST=192.168.88.1 \
    -e MIKROTIK_USERNAME=sshuser \
    -e MIKROTIK_PASSWORD=your_password \
    -e MIKROTIK_MCP__TRANSPORT=sse \
    mikrotik-mcp

# Server is up:
#   SSE:             http://localhost:8000/sse
#   Streamable HTTP: http://localhost:8000/mcp
#   Health probe:    GET /health
05 — Language server

Catch it in the editor, not on the router.

routeros-lsp is a Language Server Protocol server for RouterOS scripts (.rsc). Your editor — or your AI coding agent — gets immediate feedback while the script is being written: syntax errors, unknown menus, commands and parameters, and the variable-scope mistakes RouterOS only reveals at import time. A sibling of MikroTik MCP; it works on its own.

routeros-lsp · RouterOS 7.21.4
guest-vlan.rsc2 errors2 warnings
# Guest VLAN
:local vlanId 200
/interface vlan add name=vlan200 vlan-id=$vlanId interface=ether1
/ip adress add address=192.168.200.1/24 interface=vlan200
/ip pool add name=pool-200 ranges=192.168.200.10-192.168.200.100
/ip firewall nat add chain=srcnat action=masquerade # WAN
:set vlanId 201
Problems2 errors2 warnings
vars/local-out-of-scopedeviceLn 3, Col 42

$vlanId is a local variable of an earlier line or of a block that has ended, so it is empty here (an imported file gives every line its own scope). Use ':global vlanId' or put the commands in one { } block. (RouterOS behaviour that the documentation does not describe)

schema/unknown-commanddeviceLn 4, Col 5

'adress' is not a menu or command in /ip of the RouterOS 7.21.4 command database. Did you mean 'address'? (RouterOS behaviour that the documentation does not describe)

schema/unexpected-argumentdeviceLn 6, Col 53

This command takes no unnamed arguments, and a '#' only starts a comment at the beginning of a command, so RouterOS reads this as an argument. Put ';' before the comment. (RouterOS behaviour that the documentation does not describe)

vars/set-undeclareddeviceLn 7, Col 6

':set vlanId' needs 'vlanId' to be declared first, with ':local vlanId' or ':global vlanId' earlier in the same block or in a block around it. 'vlanId' is declared elsewhere in this file, but each line of an imported file is its own scope and a block that has ended hides its names. Declare it again here or put the commands in one { } block. (RouterOS behaviour that the documentation does not describe)

Built to stay quiet when you're right. Checked against RouterOS 7.21.4 on 16,900 generated command lines, it never reported one the router accepts. It does miss some the router rejects — mostly the kinds it doesn't check, like parameter values. Method and limits →

Diagnostics

Syntax, variables, menus and commands: 36 rules, each with an id, a severity and a label for how well founded it is. Messages say what RouterOS will do and how to fix it.

Completion and hover

Menus, commands and parameters (required first), values after name=, variables in scope. Hover shows the description, type and values from the command database.

Outline and folding

Functions, :global and :local declarations and the menu headers of an export fill the outline; blocks, continued lines and comment runs fold.

Command line

routeros-lsp check runs the same analysis for CI, a pre-commit hook, or a script an agent just wrote. Exit status 1 when it finds errors.

Install

One command. No dependencies.

# Python 3.10+
$ pipx install routeros-lsp     # or: uv tool install routeros-lsp
$ routeros-lsp --version
$ routeros-lsp check scripts/     # exit 1 when there are errors
